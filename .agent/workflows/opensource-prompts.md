# 🔓 代码开源 AI 提示词模板

> 以下提示词可直接复制使用，用于指导 AI（如 Claude、GPT、Gemini 等）进行代码开源前的审查和调整。

---

## 📋 一、完整开源审查提示词

```
请对以下代码进行开源前审查，按照以下检查项逐一分析并给出修改建议：

## 1. 隐私和敏感信息检查
- 硬编码的文件路径（如 /home/username/, /Users/xxx/）
- API 密钥、Token、密码等凭证
- 内部服务器地址、IP、端口
- 个人邮箱、用户名、员工信息
- 数据库连接字符串
- 许可证密钥

## 2. 无用代码清理
- 未被调用的函数和类
- 注释掉的旧代码块
- 调试用的 print/console.log 语句
- 空的或仅有 pass 的函数
- 重复的代码逻辑
- 未使用的导入/import

## 3. 代码注释规范
- 函数/类是否有 docstring 说明
- 复杂逻辑是否有行内注释
- 注释是否与代码一致（非过时注释）
- 是否有 TODO/FIXME 需要处理

## 4. 代码质量
- 变量命名是否清晰
- 是否有 magic number 需要定义为常量
- 错误处理是否完善
- 是否符合语言编码规范

请按以下格式输出：
### 发现的问题
[列出每个问题，标注行号和问题类型]

### 修改建议
[给出具体的修改代码或建议]

### 修改后的完整代码
[输出清理后的代码]
```

## 🔒 二、隐私信息专项检查提示词

```
请检查以下代码中的隐私和敏感信息，识别并提供替换方案：

检查清单：
1. 硬编码路径 → 替换为环境变量或相对路径
2. API 密钥/Token → 替换为环境变量读取
3. 密码/凭证 → 替换为配置文件或环境变量
4. 内部 URL/IP → 替换为配置项
5. 个人信息 → 使用占位符替代
6. 调试输出 → 删除或替换为日志

输出格式：
| 行号 | 问题类型 | 原内容 | 建议替换为 |
|-----|---------|-------|----------|

最后，请输出完整的修改后代码。
```

## 🗑️ 三、无用代码清理提示词

```
请分析以下代码，识别并清理无用代码：

## 检查项

### 1. 死代码（Dead Code）
- 永远不会被执行的代码分支
- 未被调用的函数、方法、类
- 未使用的变量

### 2. 调试代码
- print() / console.log() 调试语句
- breakpoint() / debugger 断点
- pdb.set_trace() 等调试器调用

### 3. 注释代码
- 被注释掉的代码块（超过3行）
- 过时的 TODO/FIXME 注释

### 4. 冗余代码
- 重复的逻辑（可抽取为函数）
- 永远为 True/False 的条件判断
- 多余的 return/break/continue

### 5. 未使用的导入
- import 了但未使用的模块

请输出：
1. 可删除的代码列表（附行号和原因）
2. 可优化的代码（附建议）
3. 清理后的完整代码
```

## 📝 四、代码注释规范化提示词

```
请为以下代码添加/规范注释，遵循以下标准：

## Python 代码注释规范

### 1. 模块级注释（文件开头）
"""
模块名称：xxx
功能描述：xxx
作者：xxx
创建日期：xxx
"""

### 2. 函数/方法 Docstring
def function_name(param1: type, param2: type) -> return_type:
    """
    函数功能的简短描述。

    更详细的说明（如果需要）。

    Args:
        param1: 参数1的说明
        param2: 参数2的说明

    Returns:
        返回值说明

    Raises:
        可能抛出的异常

    Example:
        >>> function_name(1, 2)
        3
    """

### 3. 类 Docstring
class ClassName:
    """
    类的简短描述。

    更详细的说明（如果需要）。

    Attributes:
        attr1: 属性1说明
        attr2: 属性2说明
    """

### 4. 行内注释
- 解释"为什么"而不是"做什么"
- 放在代码上方或同行末尾
- 保持简洁，不超过80字符

请为代码添加适当的注释，输出完整的注释后代码。
```

## 🔄 五、快速清理提示词（简洁版）

```
请对代码进行开源前快速清理：

1. 删除：硬编码路径、API密钥、调试print、注释代码块、未使用的import
2. 替换：敏感信息用环境变量、magic number用常量
3. 添加：关键函数的docstring、复杂逻辑的注释
4. 检查：变量命名、代码格式

直接输出清理后的代码，在代码上方用 `# CHANGED:` 标注修改点。
```

## 🎯 七、分步骤清理提示词（对话式）

用于分步骤与 AI 交互：

```
# 第一步：分析
请分析这段代码，列出所有需要开源前处理的问题（不要修改代码）。

# 第二步：隐私清理
请处理刚才列出的隐私相关问题，输出修改后的代码。

# 第三步：无用代码
请继续清理无用代码（调试语句、未使用的函数等）。

# 第四步：注释规范
请为关键函数添加 docstring 和必要的行内注释。

# 第五步：最终检查
请最终检查代码，确保符合开源标准，输出完整代码。
```

## ⚙️ 八、针对特定语言的提示词

### Python 版本
```
请按照 PEP8 和 Google Python Style Guide 规范审查此 Python 代码：
1. 移除敏感信息（路径、密钥、调试语句）
2. 使用 typing 添加类型注解
3. 添加 docstring（Google 风格）
4. 清理未使用的 import（可用 isort 排序）
5. 格式化代码（符合 black 标准）
```

### JavaScript/TypeScript 版本
```
请按照 ESLint 和 Prettier 规范审查此 JS/TS 代码：
1. 移除敏感信息（配置用 .env）
2. 添加 JSDoc 注释
3. 删除 console.log 调试语句
4. 清理未使用的 import
5. 使用 const/let 替代 var
```

---

## 💡 使用技巧

1. **先分析后修改**：先让 AI 列出问题，确认后再修改
2. **分批处理**：大文件分段处理，避免遗漏
3. **保留原文件**：修改前备份，方便对比
4. **自动化验证**：修改后用 lint 工具验证
